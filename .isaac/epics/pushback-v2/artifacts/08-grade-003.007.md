## Weaknesses + risks

- **L-001 (minor):** The `truncateExcerpt` function does `text.slice(0, EXCERPT_MAX_CHARS).lastIndexOf(' ')` then `slice(0, lastSpace)`. The resulting string is at most `EXCERPT_MAX_CHARS - 1` (because the last char before the space is at index `lastSpace - 1`). When concatenated with `" — "` (3 chars), the final length is `EXCERPT_MAX_CHARS - 1 + 3 = EXCERPT_MAX_CHARS + 2`. The component-level cap is therefore **not strict 240** — it's "240 minus one word plus 3-char ellipsis". The AC says "truncated at `EXCERPT_MAX_CHARS`". Defensible if we treat the cap as a soft cap on excerpt-body length and " — " as visible suffix, but worth a test assertion: final rendered text length ≤ EXCERPT_MAX_CHARS + 3 to make the contract explicit. **Implementation: add the +3 tolerance to the truncation assertion in the test.**

- **L-002 (minor):** The plan says `getJudgesForSlug` already catches its own errors and returns null. True. The outer `.catch()` in `getAllFieldwork` is therefore mostly belt-and-braces. The defence is justified (covers a module-load failure or unexpected throw), but the comment in the code should make this explicit so a future reader doesn't think "double error handling — refactor".

- **L-003 (minor):** Plan adds `pushback` as a **required** field on `Fieldwork`, which propagates type errors across the test surface. Plan does identify and list the fixture sites, but doesn't explicitly call out that a `pnpm typecheck` immediately after the type change will produce a wave of errors, all of which are mechanical. **No fix needed in the plan — just a heads-up to the implementer.** Could have called this out as a "yes I know this looks alarming" footnote.

- **M-001 (medium):** Plan does NOT explicitly cover the case where `getJudgesForSlug` succeeds but returns an enrichment with empty `excerpts: []` (e.g. count > 0 but every excerpt is null). The PushbackSummary will render the count header but no blockquotes. That's the correct behaviour, but it's not tested. **Add a test case: count=2, landed=0, excerpts: [] → header rendered, no blockquotes, no landed line.** Cheap to add.

- **L-004 (minor):** The plan specifies `aria-label="Pushback summary"` on the `<section>`. British English convention would lowercase. Project voice is lowercase. But screen-reader announcement should still read sensibly — sentence case is fine here. Defensible either way; flagging for Maria's voice-check.

- **L-005 (minor):** Plan does not specify behaviour for the `landed` line when `landed === count` (every pushback landed). The fact that it renders as `landed (n)` is fine; no special-case needed. Worth a comment in the test to confirm we don't bother with "all of them landed" copy.

- **L-006 (minor):** Plan assumes `EXCERPT_MAX_CHARS` is exported from `@/lib/argue-judge/schema`. Confirmed by reading the schema file. Plan is correct, just noting the dependency.
