# Story 005.002: `VideoLoop` extension — `pauseWhenOffscreen` prop

## Description

Add an optional `pauseWhenOffscreen?: boolean` prop to `src/components/VideoLoop.tsx`. When `true`, the IntersectionObserver stays alive for the component's lifetime and toggles play/pause as the video enters and exits the viewport. When `false` (default), existing behaviour is preserved exactly — IO disconnects after first intersection. This unlocks the gallery's requirement of one-video-playing-at-a-time without regressing the Fieldwork detail pages.

Backward-compatible, additive change. Regression test for the legacy (no-prop) path is the critical guard.

## Acceptance Criteria

- [ ] **AC-002.1** — When `pauseWhenOffscreen` is omitted or `false`, the IntersectionObserver disconnects after the first intersection event (matches existing behaviour). Existing `VideoLoop.test.tsx` cases pass without modification. (Maps to PRD AC-019.)
- [ ] **AC-002.2** — When `pauseWhenOffscreen={true}`, the IntersectionObserver remains active for the component's lifetime. On `isIntersecting === true`, the video plays. On `isIntersecting === false`, the video pauses.
- [ ] **AC-002.3** — Reduced-motion handling is unchanged: when `prefers-reduced-motion: reduce` is set, the video stays paused regardless of intersection state, and the `▶ play` overlay is shown.
- [ ] **AC-002.4** — `priority={true}` continues to skip the IntersectionObserver entirely (sets `inView` to `true` on mount), regardless of `pauseWhenOffscreen` value. The first gallery panel needs both `priority={true}` AND `pauseWhenOffscreen={true}` working together: it plays immediately on mount, and continues to be governed by intersection state after — pause when scrolled away, resume when back.
- [ ] **AC-002.5** — Cleanup: when the component unmounts, the IntersectionObserver is disconnected regardless of `pauseWhenOffscreen` value (no observer leak).
- [ ] **AC-002.6** — TypeScript: `VideoLoopProps` adds `pauseWhenOffscreen?: boolean` as an optional property; all existing callers compile without modification.
- [ ] **AC-002.7** — Quality gates: `pnpm typecheck && pnpm lint && pnpm test && pnpm build` all green.

## Technical Tasks

1. **Extend `VideoLoopProps`** with `pauseWhenOffscreen?: boolean` (default semantically `false`).
2. **Refactor the `useEffect` that creates the IntersectionObserver:**
   - When `pauseWhenOffscreen === false` (default): existing behaviour — observe; on first intersection, set `inView` to `true` and disconnect.
   - When `pauseWhenOffscreen === true`: observe; on every entry, set `inView` to match `entry.isIntersecting`. Do NOT disconnect on intersection. Disconnect only on cleanup (return function).
   - When `priority === true`: skip the observer regardless (existing path; `inView` starts `true`). But if `pauseWhenOffscreen === true` AND `priority === true`, still observe to enable pause-on-scroll-away. *Adjustment from current logic — verify carefully.*
3. **Update the play/pause `useEffect`:**
   - Current: `if (inView) play()`. No pause when `inView` goes false.
   - New: `if (inView) play()` AND `if (!inView) pause()`. The pause path is now reachable when `pauseWhenOffscreen` flips `inView` to false mid-lifetime.
   - Preserve the reduced-motion + userPlay logic exactly.
4. **Tests in `src/components/__tests__/VideoLoop.test.tsx`:**
   - Verify existing test cases still pass (no modification to existing assertions).
   - Add test "with pauseWhenOffscreen and IO entry, video plays; with subsequent IO exit, video pauses"
   - Add test "without pauseWhenOffscreen prop, IO disconnects after first entry" (regression guard for AC-002.1 explicitly)
   - Add test "with priority + pauseWhenOffscreen, video plays on mount AND pauses when scrolled out"
   - Mock IntersectionObserver per existing test patterns.
5. **Run all four quality gates locally** before opening PR.

## Notes

- The trickiest case is `priority={true} + pauseWhenOffscreen={true}` — the first gallery panel scenario. Current logic short-circuits the IO when `priority === true`. New logic needs to still observe in this combined case so the panel pauses if user scrolls past. Verify with explicit test (AC-002.4).
- Be careful with `useEffect` dependencies — `pauseWhenOffscreen` is now a dependency of the IO-creation effect. Adding it to the dependency array is correct; verify no infinite-re-observe loops.
- The `play()` Promise may resolve after the video has been paused by a subsequent intersection-exit. The existing `.catch()` covers autoplay-blocked errors; consider whether play→pause→play sequences need additional guarding (likely not — browsers handle this gracefully).
